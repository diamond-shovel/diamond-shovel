# 必读

## 注意事项
* 此包的运行条件需要原生docker环境，不支持WSL提供的docker环境，实测会严重影响性能
* 因需要建立resolver，需要稳定的网络环境，应保证至少50Mbps、和主备dns延迟均小于100ms以及跃点数均小于10的有线网络接入
---
## funciton包
### function包的作用
这个包含有所有业务系统的业务  
function包下的每个文件夹都是一个业务系统  
例如info_collect，这个文件夹下面就是信息采集系统的业务  
### function包下设计规范
* 每个业务系统的业务都放在一个文件夹下
* 每个业务系统中都应有一套controller，作为系统调用的入口
* 每个业务系统应当都拒绝使用多线程，保证业务链条便于管理
### function下的特殊文件
#### binary_manager.py
因很多业务系统需要二进制文件的调用，所以  
它作为全局的二进制文件管理器，用于管理所有的二进制文件

## 业务系统
### 信息采集系统 (info_collect)
从一个或多个公司名 -> 公司的所有资产信息，包括URL、高危框架指纹识别、IP、ICP备案、域名、邮箱、电话等
### 漏洞扫描系统 (vuln_scan)
通过URL -> 该URL列表的所有漏洞  
大多使用开源可控可商用闭源的漏扫框架  
目前主要使用nuclei和自研弱口令爆破，因为它的模板化特性，可以快速开发新的漏扫模板、且支持fuzz等启发式漏扫  
### 报告生成系统 (report_generate)
漏洞 -> 漏洞报告  
主体设计思想采用模板替换的方式，即将模板中的变量替换为真实的数据
### 语言生成系统 (AIGC)
可模块化应用于以上所有系统，为决策和报告提供自然语言描述  
可用于生成工作量报告、优化建议、优化漏洞报告等
